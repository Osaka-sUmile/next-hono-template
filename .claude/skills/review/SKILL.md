# /review

コードレビュースキル。変更内容を分析し、品質・パターン・ベストプラクティスの観点からレビューする。

## 使用方法

```
/review [対象]
```

## 対象の指定

- `staged`: ステージングされた変更をレビュー
- `PR#123`: 指定PRをレビュー
- `file.ts`: 特定ファイルをレビュー
- 指定なし: 未コミットの変更をレビュー

## レビュー観点

### 1. コード品質
- 型安全性（any型の使用禁止）
- エラーハンドリング
- 命名規則の一貫性
- コードの重複

### 2. プロジェクト規約
- フロントエンド: `docs/frontend-guidelines.md`, `docs/architecture.md`
- バックエンド: `docs/architecture.md`

### 3. セキュリティ
- 認証・認可チェック
- 入力バリデーション
- 機密情報の取り扱い

### 4. パフォーマンス
- 不要な再レンダリング
- N+1クエリ
- メモ化の適切な使用

## レビュー結果フォーマット

```markdown
## 概要
変更の要約

## 良い点
- ポジティブなフィードバック

## 改善点

### 必須（Must Fix）
- 修正が必要な問題

### 推奨（Should Fix）
- 改善を推奨する点

### 提案（Nice to Have）
- オプションの改善提案

## 詳細コメント

### `path/to/file.ts`
- L10: コメント内容
```

## フロントエンド特有のチェック

- テーマ値の使用（ハードコード色禁止）
- 統一コンポーネントの使用
- `apiClient`の使用（直接fetchの禁止）
- i18n対応（ハードコード文字列の確認）

## バックエンド特有のチェック

- Swagger定義の存在確認
- 認証・認可ミドルウェアの適用
- Zodバリデーションの実装
- Repository/Logic/Serviceの責務分離
